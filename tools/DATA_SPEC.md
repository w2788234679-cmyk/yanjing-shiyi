# 北京文化旅行应用 · 景点数据 Schema 规范

所有景点数据统一写入 `data/part_N.json`，UTF-8 无 BOM，纯 JSON 数组，不要注释、不要尾随逗号、字符串内换行用 `\n`。
每个元素是一个景点的完整数据对象，字段顺序与下方保持一致。

## 通用字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 唯一英文 slug，全小写连字符，如 `gugong`、`tiananmen` |
| `name` | string | 标准名称，如「故宫博物院」 |
| `alias` | string[] | 别称、俗称、曾用名，2-4 个 |
| `category` | string | 所属大类，只能取：`皇家宫殿`/`长城关隘`/`皇家园林`/`博物馆艺文`/`宗教古迹`/`城市场景` |
| `district` | string | 所在行政区，如「东城区」「昌平区」 |
| `visitTime` | string | 建议游览时长，如「3～4 小时」 |
| `ticket` | string | 门票信息，如「旺季 60 元 / 淡季 40 元」 |
| `coords` | [number, number] | 纬度在前、经度在后，保留 4 位小数 |
| `summary` | string | 一句话概述，30～50 字，要有画面感，不要空话 |
| `highlights` | string[] | 3～5 个必看点，短词，如「太和殿」「珍宝馆」 |

## `history`：历史沿革（4～6 条，按时间升序）

```json
{ "era": "明永乐四年（1406）", "title": "诏建紫禁城", "text": "text 内容 100～140 字" }
```

## `facts`：近代趣闻（3～4 条）

```json
{ "title": "标题 8～14 字", "text": "100～160 字，务必具体、有细节、有出处感，避免空泛抒情" }
```

## `figures`：相关名人（3～4 位）

```json
{ "name": "人物名", "role": "身份定位，如「明成祖朱棣」", "text": "90～150 字，写清此人与该景点的具体关联" }
```

## `artifacts`：馆藏文物与遗迹（3～5 条）

```json
{ "name": "文物/遗迹名", "where": "所在位置，如「乾清宫东暖阁」", "text": "80～140 字" }
```

## `clues`：故事线索（3～4 条，游玩探索用）

```json
{
  "q": "线索设问，20～30 字，引导游客在现场去找答案",
  "hint": "现场提示，15～25 字，指向能看到的实物",
  "answer": "答案，10～20 字",
  "reveal": "揭晓后的故事，100～150 字"
}
```

## `stories`：典故故事（2～3 条，用于画廊图片点击后阅读）

```json
{ "id": "gugong-zhuni", "title": "故事标题", "subtitle": "副标题/出处", "text": "200～350 字，叙事流畅，有情节" }
```

`id` 命名规则：`<景点id>-<英文短名>`。

## `galleries`：图片集合分组（2～3 组）

```json
{
  "name": "分组名，如『一砖一瓦』",
  "items": [
    { "caption": "图注，10～20 字", "story": "关联到 stories 里的 id；无则留空字符串", "image": "" }
  ]
}
```
每个分组 3～5 项。

## 写作硬性要求

1. **事实必须准确**：年代、人物、事件、文物名称不能编造。不确定的写「相传」「据记载」，不要硬编年份。
2. **不要写成百科词条**:要有细节、有画面、有语气，像一个懂行的朋友在讲。
3. 禁止出现「AAAAA 级」「值得一游」「美的不要不要」这类旅游文案腔。
4. 涉及近现代史保持客观、尊重，不评价、不虚构。
5. 每景点总字数 1600～2400 字。
